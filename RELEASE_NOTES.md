# Laser 0.15.0 — the project lifecycle leap

Your work now lives in the project, not in a conversation. Write a Spec,
research it with cited sources, design it, plan it, and let Tasks carry the
work — across as many sessions as it takes, and through restarts, moves and
worktrees.

## The workspace

- **Work, Board and Needs you.** Every Spec, Research, Design, Plan and Task
  has a key you can say out loud (`SPEC-1`, `TASK-7`), a state you can see, and
  a place in the lists. The Board moves Tasks by their own rules and refuses a
  move that the plan does not allow, in words.
- **`/spec`, `/research`, `/design` and `/plan` work alone**, from any chat. No
  Spec is required to start researching; a chat with no project asks which one.
- **Comments, reviews and approvals** sit on the exact revision they are about.
  An approval covers the bytes it approved — change them and it says so.

## Research

A Research artifact is a question tree that findings answer, each with a source,
a digest and a confidence the app assigns by rule rather than by vibe. The
adapters are the web, this project, a repository, a package and a document, each
with its own budget. A running search is now a **Command** in the fleet: you can
see what it is spending and stop it, and the findings it already recorded stay.

## Design

The Design Index reads your project without running it, and says what it really
found — React, Rails or neither. A Sketch grounds into a Tree whose nodes are
either mapped to something that exists or honestly marked Proposed. For a
greenfield project, Foundation proposes tokens, type and components and touches
nothing in your repository until you say Start.

## Building, and proving it

- An attempt links to the real checkpoints, diffs and commits it came from.
- **Verification** runs the Task's own commands, reads the Spec, Design, Plan
  and Task as four authorities, and reports what it proved. A passing run asks
  for your review; it never marks the work done by itself.
- **Native evidence is yours.** A visual criterion is satisfied by a checkpoint
  preview you accepted — per repository the work touched — and what you accepted
  is kept where it can still be read, even after the checkpoint is pruned.
- **The proof trail** shows the exact source a decision rested on, out of the
  evidence that decision bound, not whatever the record points at today.

## Keeping your work

- Move a project folder and it is still the same project, with its history.
  Copy one and Laser asks which you meant rather than merging two histories.
- Delete a session and the work it made stays; its links say the session is
  gone. Remove a project and its work is hidden until you delete it explicitly.
- Storage has a budget that counts everything canonical, refuses honestly when
  it is full, and never quietly deletes history to make room.

## Also in this release

- Background work is called a **Command** everywhere a person reads it.
- Scrolling up in a long conversation keeps working after a compaction.
- A message to an agent that finished reopens it instead of calling it unknown.
- Large session lists page properly again, and a cold project starts faster.
